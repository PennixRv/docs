## v0.6 已交付

### 跨会话记忆底座（`trellis mem`）

本地 CLI，索引当前支持的 AI 会话日志并提供结构化检索。`trellis mem list`、`search`、`context`、`extract`、`projects` 分别用于发现会话、关键词搜索、上下文窗口查询、清洗后对话导出和按项目路由。`extract --phase brainstorm|implement|all` 按任务创建与实施开始边界切分会话。可复用检索 / 阶段切片逻辑封装在 `@pennixrv/trellis-core/mem`；纯本地，不上传任何内容。

### Session insight（以能力 skill 形式交付）

最终以内置 `trellis-session-insight` Skill 形式交付，而不是硬编码为工作流步骤。这条 Skill 说明 AI 何时查询 `trellis mem`（过往解法、决策、跨会话进度、相似 Bug 和会话回顾），以及如何按当前情境使用结果：行内引用、更新任务产物或相关 spec、追加任务记录，或仅作为背景信息。它不规定固定的写回文件。

### 可配置 Hooks

Hook 行为由 `.trellis/config.yaml` 驱动。当前设置包括 `session_commit_message`、`max_journal_lines`、`session_auto_commit`、`hooks.after_create`、`after_start`、`after_finish` 和 `after_complete` 任务生命周期命令、`channel.worker_guard.idle_timeout` 与 `max_live_workers`，以及 `codex.dispatch_mode`（`auto` 或 `inline`；`sub-agent` 仍是 `auto` 的兼容别名）。

### Auto runner —— 已被替代

从 roadmap 中移除。Claude Code（`/goal`）和 Codex（autonomy mode）现在都原生提供多步自主推进。Trellis 再在上面加一层 runner 不会跟平台调度器互补，反而会冲突。

## 延期

### Spec → Wiki 概念迁移

灵感来自 [Karpathy 的 LLM Wiki 模式](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：把 `spec` 概念扩展成更通用的"项目记忆 / 知识库"层，带 wikilinks、交叉引用、过期标记；spec 收窄到纯 coding 约束，wiki 承接更广义的项目记忆。

**状态：因产品原因延期。** 0.6 周期优先做了记忆底座（`trellis mem`）和消费它的 session-insight skill —— 这两件事已经覆盖了最常见的回忆需求，团队不需要被强制把 `spec/` 迁到新结构。Wiki 仍然在 roadmap 上，但不再卡 0.6。

## 后续设想

早期的 v0.7 提案不代表当前发布承诺。当前 native workflow 由五个阶段专用 Skill
协作，并将任务生命周期与阶段路由分开。团队级记忆和更广泛的项目知识管理仍可作为
未来方向，但不属于 0.7.1 发布内容。

此前关于加强 brainstorm 的设想，已由目标探索、决策和方案设计阶段承接，不再作为
独立 brainstorm Skill。当前 native workflow 和阶段 Skill 已包含中文内容；本次发布
不宣称所有 CLI 消息和各平台模板都已完成中文本地化。
