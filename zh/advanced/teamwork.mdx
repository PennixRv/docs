Trellis Teamwork 是面向用户的协作入口，用于运行有界的 teammate 进程和维护持久讨论。公开 CLI 命令为 `trellis teamwork`，底层沿用 Trellis Core 的 Channel 事件和存储模型。

根据工作类型选择入口：

| 需求                               | Teamwork 方式    |
| ---------------------------------- | ---------------- |
| 一个边界明确的问题、调查或审查     | `teamwork run`   |
| 多个独立工作单元，共用一个完成收据 | `teamwork batch` |
| 需要持续记录评论、状态和结论的主题 | Forum 与 thread  |

所有 teammate 共用一张通用角色卡，负责调查、研究、审查、验证和撰写分配的报告；不实现产品代码，也不启动嵌套代理。固定批次通过一份计划一次提交；提交后由程序负责派发、等待、重试判定、产物检查和终态收据。

## 运行一个有界任务

当一个 teammate 就能返回完整答案时，使用 `teamwork run`。在提示中写明问题、证据范围和报告要求：

```bash
trellis teamwork run design-review \
  --provider codex \
  --message '审查设计中的失败场景，引用仓库路径，不要修改产品源码。' \
  --timeout 10m
```

成功时，命令打印最终回答并删除临时 Teamwork session；失败时保留 session 供检查。需要检查运行状态或停止进程时，使用 `trellis teamwork list`、`trellis teamwork messages <name>` 和 `trellis teamwork kill <name> --as <teammate>`。

## 提交固定批次

当所有独立工作单元的目标、只读范围、报告位置、验收条件、teammate 配置和单项重试次数都能在派发前确定时，使用固定批次，并一次提交完整计划：

```bash
trellis teamwork batch .trellis/tasks/<task-id>/teammates/<batch-id>/plan.json
```

提交后等待程序返回终态收据。在批次运行期间，不检查部分报告、不手动派发替代任务、不自行选择重试，也不向 teammate 追加指令。程序按 FIFO 队列为空出的容量补位，并依照每个工作单元自己的重试上限完成结算。超时会继续同一 attempt；确认执行失败或验收失败后，程序才可能在该单元额度内创建新 attempt。结果未知时必须先核对状态，不能重复派发。

当前版本尚无通过能力门禁的 teammate 宿主 adapter，因此批次命令会在写入协调状态前拒绝执行。不要用逐个手动启动 teammate 的方式绕过这个限制。存在 provider 合同或配置好 CLI，并不代表宿主已经通过能力门禁。

收到终态业务收据后，再依据所属 Trellis task 检查已接受的报告，在 task 中处理最终失败，并继续原生的实现、测试、审查和状态管理流程。

## 独立评议

顾问式评议是一个普通工作单元，提交带证据的建议。委员会由同一批次中的两个独立评议组成：两者使用相同的冻结问题和验收合同，分别采用不同视角，并保持证据不重叠。Teammate 之间不交换发现，也不根据对方报告修改自己的结论。只有整个批次收到终态收据后，主代理才能比较报告；其中任何一个工作单元最终失败，委员会结果就属于未完成。

## 维护持久讨论

需要持续记录主题讨论时，创建 forum：

```bash
trellis teamwork create design-feedback \
  --type forum \
  --description '设计反馈和后续决策。' \
  --by main

trellis teamwork post design-feedback opened \
  --as main \
  --thread error-recovery \
  --title '错误恢复行为' \
  --description '记录恢复行为相关证据与决定。' \
  --text '每个审查主题使用独立 thread。'

trellis teamwork forum design-feedback
trellis teamwork thread design-feedback error-recovery
```

使用 `teamwork post` 添加评论、状态或摘要。阅读时使用 forum 和 thread 命令查看归并后的状态；它们会处理 thread 生命周期事件。

## 命令参考

常用命令包括 `create`、`run`、`batch`、`spawn`、`send`、`wait`、`messages`、`interrupt`、`kill`、`forum`、`thread`、`post`、`context` 和 `prune`。运行 `trellis teamwork --help` 或 `trellis teamwork <command> --help` 查看当前 CLI 的完整参数。

公开命令和内置 Skill 统一使用 Teamwork 名称。“Channel”仍是底层 Core 协作模型及其持久化事件合同的名称。

另见 [Beta 版 Teamwork 指南](/zh/beta/advanced/teamwork)。
