本版本按已批准工作流设计进行第二轮复审，修复阶段返修、独立委派准入及 Teamwork 锁竞争问题。

实施合同已接受、实施尚未授权时，可以显式退回解决方案设计与收敛阶段或更早受影响阶段。受影响的接受与授权随之失效；修订后的产物须重新接受，再核验实施授权。

实施准入现在要求当前实施阶段为 active，blocked 或 waiting_user 不允许启动委派。受控 `delegate-start` 还会核验父任务的会话归属围栏，在调用 Paseo 前拒绝已完成或取消的子任务。这些检查沿用 teammate 的角色职责，不增加 provider 权限隔离。

CLI 与 Core 均保留空锁或格式异常的锁，只把 `ESRCH` 作为持有进程已退出的证据，权限错误不能触发抢锁。死锁回收使用独占保护文件并重新核验持有者，避免多个回收者删除刚建立的新锁。中断后残留的 `<lock>.recovery` 会保留；核实回收已停止并显式处理该现场前，获取锁按原超时失败。

通过原生项目更新刷新受管脚本与阶段 Skills。现有任务和交接历史保持当前状态及位置。managed batch 派发仍要求已核验的 host adapter。
