## 问题修复

模板跟踪现排除运行态、会话交接包和 Python 字节码。`trellis update` 也会从已有清单中移除误收录的哈希键，只修正管理记录，保留运行文件和已有任务记录，同时保留用于识别 workflow/config 本地修改的模板基线。

清理时也保留 registry 管理的 spec 基线，包括已被本地修改的 spec。已有运行文件和旧任务记录保持原样。

阶段转换现会撤销受影响的跳过决定，并在接受结果、完成或取消任务前重新核验已接受产物。实施授权绑定合同内容摘要，省略设计阶段的路线也适用。交付审查已接受、任务尚未结束时，可以重新审查或按影响回流。

所有交互 teammate 都会收到研究、审查、验证的角色和结果要求，包括未指定 `--agent` 的调用。源码和 Git 写入边界通过角色约束，批次启动快照不再声明这两项具备宿主权限隔离。随附报告示例补齐冻结计划和阶段 revision。Teamwork 指引区分 `general`、Advisor、committee 与运行命令，并明确公开 `batch` 入口仍不可用。

本版包含 beta.2、beta.3 的 Teamwork 能力迁移、按哈希保护的旧生成资产清退、平台重新初始化保护和宿主等待续接约束。安装 `0.7.1-beta.4` 后运行 `trellis update`，即可应用完整修复。
