## What slash commands do

Slash commands are shortcuts. Instead of explaining what you want, you type `/command` and the AI knows the workflow.

Trellis ships a small command surface for session boundaries. Most workflow actions are now auto-trigger skills or sub-agents. You can add your own commands for project-specific entry points.

## Built-in commands

### Session boundaries

| Command                | What it does                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `/trellis:start`       | Manual start workflow for platforms without automatic session injection. Hook / extension platforms load context automatically. |
| `/trellis:continue`    | Continue the current session task at the next workflow step.                                                                    |
| `/trellis:finish-work` | Record session progress in the developer journal; does not complete a task.                                                     |

### Development workflow

| Phase Skill                                       | What it does                                           |
| ------------------------------------------------- | ------------------------------------------------------ |
| `trellis-goal-exploration-and-requirements`       | Establish and confirm the task's current requirements. |
| `trellis-decision-space-construction-and-merging` | Identify and organize material decisions.              |
| `trellis-solution-design-and-convergence`         | Accept an analysis result or implementation contract.  |
| `trellis-task-implementation`                     | Implement and verify an authorized contract.           |
| `trellis-delivery-review-and-closeout`            | Review delivery and determine task disposition.        |

### Maintenance

| Supporting Skill          | What it does                                                  |
| ------------------------- | ------------------------------------------------------------- |
| `trellis-teamwork`        | Coordinate teammate work when the task benefits from it.      |
| `trellis-session-insight` | Recall relevant prior decisions or conversation evidence.     |
| `trellis-spec-bootstrap`  | Draft or refresh specs from the current codebase when useful. |
| `trellis-meta`            | Understand or customize Trellis project assets.               |

The `trellis-research`, `trellis-implement`, and `trellis-check` entries are sub-agent definitions, not Skills.

The phase Skills provide separate procedures and diagrams. Trellis CLI records the selected business-phase route independently from task lifecycle status. `task.py complete` and `task.py cancel` update task lifecycle during closeout; `finish-work` only records session progress. See [How the Trellis Workflow Works](/start/how-it-works).

## Using commands

Type the command in Claude Code:

```
/trellis:continue
```

The command expands into a full prompt that tells the AI what to do. You don't see this prompt, but the AI follows it.

## Creating custom commands

Commands are markdown files in `.claude/commands/`. Create a new command:

```bash
mkdir -p .claude/commands/my-project
```

Create `.claude/commands/my-project/deploy-check.md`:

```markdown
Before deploying, check:

1. All tests pass: `npm test`
2. No TypeScript errors: `npm run typecheck`
3. Lint clean: `npm run lint`
4. Build succeeds: `npm run build`

Run each check and report results. If any fail, explain what's wrong.
```

Now `/my-project:deploy-check` is available.

## Command structure

A command file is just a prompt. When you invoke the command, the file contents become instructions for the AI.

Good commands:

- Have clear steps
- Include actual commands to run
- Specify what output to expect
- Tell the AI what to do if something fails

Bad commands:

- Are vague ("check the code")
- Don't specify how to check
- Leave the AI guessing

## Namespacing

Commands use the folder name as a namespace:

```
.claude/commands/
├── trellis/           # /trellis:* commands
│   ├── finish-work.md
│   └── continue.md
└── my-project/        # /my-project:* commands
    └── deploy-check.md
```

Keep your project commands in a separate folder from Trellis commands. This avoids conflicts when Trellis updates.

## Arguments

Commands can accept arguments. Reference them with `$ARGUMENTS` in the command file:

```markdown
Review the file at $ARGUMENTS.

Check for:

- Type safety
- Error handling
- Test coverage
```

Usage: `/my-project:review src/api/users.ts`

The AI receives the prompt with `$ARGUMENTS` replaced by `src/api/users.ts`.
