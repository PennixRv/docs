## Appendix B: Command & Skill Cheat Sheet

Trellis provides platform-specific session commands, bundled Skills, and the task CLI. Which native command or agent surface is available depends on the host platform.

### Slash Commands (per platform)

`finish-work` and `continue` are the normal user-invoked commands. `start` is only user-facing on platforms that do not auto-inject session context.

| Platform                                                | Start                                                                     | Finish                 | Continue             | Delivery form                          |
| ------------------------------------------------------- | ------------------------------------------------------------------------- | ---------------------- | -------------------- | -------------------------------------- |
| Claude Code / OpenCode / Gemini CLI / CodeBuddy / Droid | automatic SessionStart hook                                               | `/trellis:finish-work` | `/trellis:continue`  | Slash command                          |
| Cursor / Pi Agent / Qoder                               | automatic SessionStart hook or extension                                  | `/trellis-finish-work` | `/trellis-continue`  | Native command / prompt                |
| Kiro                                                    | `@trellis:start`                                                          | `@trellis:finish-work` | `@trellis:continue`  | Skill via `@` picker                   |
| Kilo                                                    | `/start.md`                                                               | `/finish-work.md`      | `/continue.md`       | Workflow file (`.kilocode/workflows/`) |
| Antigravity / Devin                                     | workflow picker → `start` / `finish-work` / `continue`                    |                        |                      | Workflow file                          |
| GitHub Copilot                                          | Run Prompt → `trellis-start` / `trellis-finish-work` / `trellis-continue` |                        |                      | Prompt file (`.github/prompts/`)       |
| Codex                                                   | automatic `AGENTS.md` prelude; optional UserPromptSubmit hook             | skill / prompt entry   | skill / prompt entry | Skills + hooks                         |

### Bundled Skills

The five phase Skills provide the detailed procedure for each workflow phase. The other bundled Skills support project customization, session history, specification work, and collaboration.

| Skill                                             | Purpose                                                |
| ------------------------------------------------- | ------------------------------------------------------ |
| `trellis-goal-exploration-and-requirements`       | Establish and confirm the task requirements.           |
| `trellis-decision-space-construction-and-merging` | Identify and resolve material decisions.               |
| `trellis-solution-design-and-convergence`         | Form and converge the implementation contract.         |
| `trellis-task-implementation`                     | Implement and verify authorized work.                  |
| `trellis-delivery-review-and-closeout`            | Review delivery and determine task closeout.           |
| `trellis-meta`                                    | Inspect and customize the Trellis assets in a project. |
| `trellis-session-insight`                         | Recall relevant prior sessions through `trellis mem`.  |
| `trellis-spec-bootstrap`                          | Create or refresh project-specific specifications.     |
| `trellis-teamwork`                                | Coordinate work through Trellis Teamwork.              |

### Native agents

Trellis integrates with the agent mechanisms provided by each host. The workflow can run in the main session or delegate work when the host and task support it; it does not require a fixed set of agent names. See [Multi-platform support](./multi-platform) and [Teamwork](./teamwork).

### Global CLI Commands

| Command           | Purpose                                              | Usage                                          |
| ----------------- | ---------------------------------------------------- | ---------------------------------------------- |
| `trellis upgrade` | Upgrade the globally installed Trellis CLI package   | `trellis upgrade [--tag <tag>]`                |
| `trellis update`  | Sync the current project's Trellis files to this CLI | `trellis update [--dry-run] [--migrate] [...]` |

### `task.py` Subcommands

| Subcommand    | Purpose                                                              | Usage                                                               |
| ------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `create`      | Create a task; title and non-empty description are required.         | `task.py create "title" --description "description"`                |
| `start`       | Set the active task for this session.                                | `task.py start <task-dir>`                                          |
| `phase`       | Inspect or update the task's phase route and phase records.          | `task.py phase show <task-dir>`                                     |
| `workflow`    | Select or clear a task-specific workflow variant.                    | `task.py workflow --help`                                           |
| `add-context` | Add a task context entry.                                            | `task.py add-context <task-dir> <file> <path> <reason>`             |
| `validate`    | Validate task context files.                                         | `task.py validate <task-dir>`                                       |
| `list`        | List tasks.                                                          | `task.py list`                                                      |
| `finish`      | Clear the active-task pointer; does not complete the task.           | `task.py finish`                                                    |
| `complete`    | Complete a task after closeout has been accepted.                    | `task.py complete <task-dir>`                                       |
| `cancel`      | Record why a task was cancelled and point to task-relative evidence. | `task.py cancel <task-dir> --reason <reason> --evidence-ref <file>` |

`complete` and `cancel` update task lifecycle. `finish` only ends the current session's task selection. Completed tasks remain in `.trellis/tasks/`.

### Python Scripts

```bash
# Context
./.trellis/scripts/get_context.py                 # Full context
./.trellis/scripts/get_context.py --json          # JSON
./.trellis/scripts/get_context.py --mode packages # Per-package spec layers (monorepo)
./.trellis/scripts/get_context.py --mode record   # For /trellis:finish-work

# Session
./.trellis/scripts/add_session.py --title "..." --commit "..." --summary "..."

# Spec bootstrap (first-time)
./.trellis/scripts/create_bootstrap.py
```
