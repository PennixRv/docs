## Main-session Hooks

Hooks supply startup context, task and phase breadcrumbs, path-scoped specs and shell session identity. Task CLI owns task state; user acceptance of the implementation contract owns authorization. Hooks do not create native subagents, rewrite delegation tool arguments or treat tool availability as permission.

Platform events, trust and activation differ. Check the generated registration files and actual host receipts. Claude Code uses `.claude/settings.json`; Codex uses `.codex/hooks.json` with host-managed activation and trust; OpenCode uses `.opencode/plugins/`; Pi and Oh My Pi use their extensions; Snow uses main-session session/user Hooks. Platforms without automatic Hooks load context through the project entry and Skills.

## Context and identity

The main session reads `prd.md`, `design.md`, the current phase and applicable specs. `implement.jsonl` and `check.jsonl` are optional, lazily created context manifests, not execution routes. OpenCode's `inject-shell-session-context.js` only forwards managed shell identity and preserves explicit identity overrides; it neither materializes roles nor starts sessions.

Before changing a Hook, read its platform reference in `trellis-meta` and its existing registration. Preserve error handling, session isolation, locks and context budgets. Do not copy credentials or runtime data. Test actual main-session event payloads, taskless and active-task cases, and explicit identity overrides.

## Update and recovery

`trellis update` uses ownership and fingerprints to delete retired native subagent Hooks and their exact registrations while preserving unrelated user settings. Modified retired execution assets, exclusions and unsafe paths block the update. Native restore interfaces reject reactivation of retired roles, executors and Hooks; history is evidence, not executable configuration.
