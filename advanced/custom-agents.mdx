## Collaboration roles and ownership

The main session owns requirements, design, implementation authorization and final acceptance. Trellis does not generate native `trellis-implement`, `trellis-check` or `trellis-research` subagents, or delegate work merely because a tool is available.

| Mechanism                 | Instance              | Boundary                                                                                                                                                |
| ------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `trellis teamwork`        | trellis teammates     | Explicit read-only questions and work packages; the main session integrates and accepts evidence                                                        |
| `paseo-based-parallelism` | paseo delegated-agent | Complete implementation packages in independent worktrees during an authorized implementation phase; the main session integrates and accepts the result |

Current roles live in `.trellis/agents/`: `teammate.md`, `teammate-profiles.json` and `teammate-profiles/` define read-only members; `delegated-worktree-primary-agent.md` and `worktree-delegation-node.md` define delegated worktree ownership. Use the native interfaces described by `trellis-teamwork` and `trellis-worktree-delegation` for instances, receipts, recovery and closure. A role file does not grant implementation permission.

Before changing a role, check its work package, phase and authorization. Members use Skills/MCP actually exposed by their host, without copying the main session identity or private configuration. They return blockers to the owner, who handles user decisions. History and recovery summaries do not expand authorization.

Kiro's `.kiro/agents/trellis.json` remains a main-session entry with native activation and trust requirements. The ordinary `trellis-check` Skill remains available for quality verification.

## Upgrade an existing project

Use `trellis update` to retire managed native roles, Hook registrations and execution configuration. Unknown ownership, user modifications, exclusions and unsafe paths block the update. Resolve the specific conflict before retrying the native update. Do not copy old templates or restore retired executors from backups. History and backups remain evidence outside current discovery.
