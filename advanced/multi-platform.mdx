## Multi-Platform and Team Configuration

Trellis ships on 22 platforms (Claude Code, Cursor, OpenCode, Codex, Kiro, Kilo, Gemini CLI, Antigravity, Devin (formerly Windsurf), Qoder, CodeBuddy, GitHub Copilot, Droid, Pi Agent, Oh My Pi, Reasonix, ZCode, Trae, Grok Build, Kimi Code, Snow CLI, DeepSeek Harness) and additionally supports any AI coding agent that reads the `.agents/skills/` standard (Amp, Cline, Deep Agents, Firebender, Warp, and more). The `.trellis/` core is identical everywhere; what differs is **how hooks, extensions, skills, and commands are delivered** on each platform.

### Joining an Already-Initialized Trellis Project

Someone else already ran `trellis init` on the repo and you're joining as a new team member. Just run `trellis init` — the CLI detects the existing setup and offers three choices:

```
? Trellis is already initialized. What would you like to do?
❯ Add AI platform(s)
  Set up developer identity on this device
  Full re-initialize
```

| Option                                       | When to pick                                                                                                    |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **Add AI platform(s)**                       | You want to add a platform others haven't configured (e.g. you use Cursor but the team only set up Claude Code) |
| **Set up developer identity on this device** | You're a new member, you just need to write your **identity** on your machine                                   |
| **Full re-initialize**                       | Project config is broken and you want a clean slate                                                             |

New members pick the second option. The CLI asks for your developer name (defaulting to your Git user), then:

- Writes `.trellis/.developer` with your developer name (gitignored, per-machine)
- Creates `.trellis/workspace/<your-name>/` for your own journal

After that, on platforms with a SessionStart hook or extension, opening a new session auto-injects Trellis context. On platforms without automatic session injection, run `/trellis:start` or the platform's start workflow.

<Note>
  Don't pick **Full re-initialize** — it overwrites existing `.trellis/`, `.claude/`, etc.
  configuration and affects the whole team.
</Note>

## Platform adapter boundaries

All 22 platforms share the `.trellis/` core, phase contracts and Skills. Generators deliver main-session Hooks, plugins, extensions, commands or Skills according to host capabilities, without native subagent roles or executors. Generated settings and actual host receipts determine activation and trust. A Codex Hook does not establish equivalent enforcement on every host; Kiro's `trellis` agent is a main-session entry.

Collaboration uses the two mechanisms in [current collaboration roles](/advanced/custom-agents): `trellis teamwork` and `paseo-based-parallelism`. Native multi-agent support never implies automatic delegation. Update older projects before adding a platform; reinitialization must not bypass retired-asset conflicts.

Verify startup context, phase breadcrumbs, specs, shell identity and Skill discovery separately. Successful generation does not certify every host event in a live session.
